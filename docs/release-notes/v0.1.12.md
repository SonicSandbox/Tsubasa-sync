**A file with a cut in it — a TV recording against a streaming subtitle — now has every line around
the break on the right side of it, and no spoken line is deleted there any more.**

Files without a cut are synced exactly as before.

---

## The lines around a cut land where they belong

A broadcast recording often carries an advert or an eyecatch the streaming release does not, so one
subtitle needs two offsets: one before the break, another after. tsubasa always found both. Where the
break *is* was only known to within a stretch — often the whole opening song — and tsubasa put it at
the start of that stretch. The lines from there to the real break then got the wrong offset, ten
seconds out; and when the subtitle had to move *back* after the break, ten seconds of lines were
removed as if they belonged to the advert.

Now the break is placed by each line's start **and end**, against the video's own subtitle track,
inside that stretch only.

| Measured on 11 real cut files | lines whose right offset their words decide | given the wrong offset | of those, deleted |
| --- | --- | --- | --- |
| 0.1.11 | 66 | 25 | 13 |
| **0.1.12** | 66 | **2** (both reported as unsure, below) | **0** |

It costs one or two milliseconds per break, and nothing for a file without one.

## New: `undetermined` — where the break may still be

Every result for a file with a cut now carries `undetermined`: per break, the stretch of video time
the break lies somewhere inside — usually the silence between two lines. `--json` prints it as
`"undetermined": [[lo, hi], ...]`; it is empty for a file with one offset. A program that cuts audio
by line (Surasura's card-making) can leave out any line that starts inside it — or inside it moved by
the jump between the two offsets, where a line given the other offset lands.

```python
for result in tsubasa.sync(tsubasa.scan("/path/to/folder")):
    result.segments        # [(272.5, 0.407), (None, -9.78)]
    result.undetermined    # [(228.4, 322.2)]
```

Thanks to **Mattias** for the report and for the pull request this is based on
([#2](https://github.com/SonicSandbox/Tsubasa-sync/pull/2)): Re:Zero, a Netflix subtitle on the
broadcast, where a line near the break played the next scene.

## Also

- A file tsubasa has already synced, synced again, is left exactly as it is. A one-offset shift of 15
  milliseconds or less is now read as no shift, where before a cut file could be rewritten twice by
  ten milliseconds before it settled.

## Getting it

**The app, no Python needed:** download `tsubasa-windows-x64.zip` below, unzip
it anywhere, double-click `tsubasa-gui.exe`. `SHA256SUMS` is the checksum.

> ⚠ Unsigned, so the first launch shows *"Windows protected your PC"* — click
> **More info**, then **Run anyway**.

**As a command or a library:**

```
pip install --upgrade tsubasa-sync
```

```
tsubasa /path/to/your/folder
```

**ffmpeg is not bundled.** Matroska files with a subtitle track inside need
nothing; any other container needs `ffmpeg` and `ffprobe` on `PATH`, or the
folder holding them in `TSUBASA_FFMPEG`.
