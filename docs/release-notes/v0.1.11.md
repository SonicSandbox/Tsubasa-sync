**Both episode numbers of a name that states two are kept, a name ending in a dash no longer hangs, and

Pairing and retiming are unchanged.

## A name with two episode numbers keeps both

Streaming releases often write a season number and the broadcast number side by side:
`葬送のフリーレン.S02E06.第34話.mkv` is season 2, episode 6 — and broadcast episode 34.

- **`episode` still reads 34**, as before: `第N話` outranks `S##E##`, and pairing keys on it.
- **New: `dual_numbering`** on every scanned file — `(2, 6, 34)` for that name, `None` for a name
  with one count. A program that numbers by season (hato, lining up a release) reads it there.

```python
video = scan.videos[0]
video.episode           # 34
video.dual_numbering    # (2, 6, 34)
```

## A name ending in a dash no longer hangs a scan

`Show - 01 - .mkv`, `Show S01E01 —.mkv`: a name that ends in a lone dash made one of the name
parsers tsubasa uses (anitopy) loop for ever — no error, the scan just never finished. The
trailing dash is now taken off before that parser sees the name. Measured over 66,789 generated
names: 882 hung before, none after, and none of the 46,696 real names tsubasa is tested on reads
differently.

## Embedded subtitles with ffprobe 4.x (Ubuntu 22.04)

An ffprobe too old to report the "metadata" flag made a WebVTT metadata track inside an MKV look
like a text subtitle, so a video could be said to have a subtitle it does not have — and a
program relying on that skipped a download it needed. tsubasa now reads the flag from ffprobe's
own track listing, for Matroska files only.

## Getting it

**The app, no Python needed:** download `tsubasa-windows-x64.zip` below, unzip
it anywhere, double-click `tsubasa-gui.exe`. `SHA256SUMS` is the checksum.

> ⚠ Unsigned, so the first launch shows *"Windows protected your PC"* — click
> **More info**, then **Run anyway**.

**As a command or a library:**

```
pip install --upgrade tsubasa-sync
```

```
tsubasa /path/to/your/folder
```

**ffmpeg is not bundled.** Matroska files with a subtitle track inside need
nothing; any other container needs `ffmpeg` and `ffprobe` on `PATH`, or the
folder holding them in `TSUBASA_FFMPEG`.
